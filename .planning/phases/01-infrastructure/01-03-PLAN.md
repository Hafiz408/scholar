  <action>

    1. Start the stack:
    ```
    docker compose up -d --build
    ```

    2. Wait for services to become healthy. Poll the backend health endpoint until it responds (max 60s):
    ```
    for i in $(seq 1 12); do
      STATUS=$(curl -s -o /dev/null -w "%{http_code}" http://localhost:8000/health 2>/dev/null)
      if [ "$STATUS" = "200" ]; then echo "Backend ready"; break; fi
      echo "Waiting... attempt $i/12"
      sleep 5
    done
    ```

    3. Check health endpoint response:
    ```
    curl -s http://localhost:8000/health
    ```
    Expected: `{"status":"ok","pgvector":"active"}`

    If pgvector is "missing": the init.sql may not have run. Check with:
    ```
    docker compose exec db psql -U scholar -d scholar -c "SELECT extname, extversion FROM pg_extension WHERE extname = 'vector';"
    ```
    If empty, the volume already existed from a previous run — fix by running `docker compose down -v` then `docker compose up -d --build`.

    4. Check frontend is responding:
    ```
    curl -s -o /dev/null -w "%{http_code}" http://localhost:3000
    ```
    Expected: 200

    5. Verify git history is clean:
    ```
    git ls-files .env
    ```
    Expected: empty output (no .env in git)

    ```
    git log --all --full-history -- .env
    ```
    Expected: empty output (no .env in any commit)

    6. Check docker compose service status:
    ```
    docker compose ps
    ```
    All three services (db, backend, frontend) should show State=running or Status=Up.

    If any check fails, diagnose and fix. Common issues:
    - Backend shows "connection refused": PostgreSQL not ready yet — wait longer or check `docker compose logs db`
    - pgvector missing: Run `docker compose down -v && docker compose up -d --build` to reinitialise volume
    - Frontend 502/error: Check `docker compose logs frontend` for npm install or build errors
